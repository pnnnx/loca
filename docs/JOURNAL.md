## 2026-10-20 — write_tests: тесты по настоящему запуску + мутационная проверка
**Что:** инструмент `write_tests` (Python, функции модуля): модель даёт только входы (`cases`), loca вызывает
функцию в отдельном процессе (дважды — ловит недетерминизм) и пишет assert / raises по настоящим результатам
(float — approx, свои исключения — по имени), прогоняет тесты, потом мутационная проверка: до 12 одиночных
порч функции (`<`↔`<=`, `+`↔`-`, `and`↔`or`, `n`→`n+1`, `True`↔`False`, `return x`→`return None`) —
непойманные показываются. Подозрительное (IndexError/ZeroDivisionError/TypeError на простых входах, всегда None)
помечается вопросом «задумано?». pytest или unittest — как в проекте; чужой файл тестов не трогает (`*_auto.py`).
**Как:** `loca/tools/testgen.py`; отказ, если модуль выполняет код при импорте или функция трогает файлы/сеть/
процессы; исходник после мутаций восстанавливается в `finally` со сверкой хеша; снимок для `/undo`.
**Зачем:** пользователь попросил авто-тесты; 7B выдумывает результаты (e07, e13), поэтому значения — только из запуска.
**Проверка:** 106 тестов (4 новых: значения из запуска и подозрительное; слабые случаи → непойманные порчи,
сильные → только эквивалентные; своё исключение и отказы; unittest). Демо на `discount`: 8/10 порч поймано,
непойманные — граница `percent > 100` (нужен случай 101).
**Коммит:** `tools: write_tests — тесты по запуску и мутационная проверка`

## 2026-10-20 — №2: приёмка «тесты <файл>» уходила в фильтр по именам → план вставал на первом шаге
**Что:** прогон `hard_width_option` на Qwen2.5-Coder-7B (облако, CPU) показал причину: модель дала подзадаче
приёмку `{"kind": "tests", "pattern": "test_config.py"}` — такого файла нет, а `pattern` уходит в
`unittest -k` (фильтр по именам тестов) → «Ran 0 tests», exit 5 → откат, план встал на n1 из 3.
**Как:** `plan.fix_test_targets` (в `plan_write`, до `narrow_acceptance`): имя файла в pattern/target →
target с реальным путём (`locate_test_file`: путь как есть или поиск по имени в проекте); файла нет →
свой тест подзадачи (`find_test_for`) или `smoke`. `RunTests.build`: для unittest target-файл запускается
через `discover -s <папка> -p <файл>` (раньше дописывался в конец команды и не работал).
`LOCA_REQUEST_TIMEOUT` — таймаут запроса к модели из окружения (на CPU первый запрос > 10 мин).
**Зачем:** узкое место №2 «не держит план».
**Проверка:** тест `test_plan_test_file_acceptance_is_real_and_runnable` (несуществующий файл → smoke,
существующий → target, имя теста не трогаем; target реально запускает 1 тест и в unittest, и в pytest);
99 тестов. Трасса прогона — `runs/hard_width_7b_cpu_stats.json`. Сквозной прогон на 7B — на Kaggle (GPU):
на CPU модель делает 5 запросов за 2 часа.
**Коммит:** `plan: приёмка «тесты <файл>» — реальный путь и запуск файла`

## 2026-10-19 — план доходит до конца: узкая приёмка подзадач
**Что:** промежуточные подзадачи больше не проверяются всем набором тестов; уже сделанная соседом
работа не блокирует подзадачу.
**Как:** `plan.narrow_acceptance` (вызывается в `plan_write`): весь набор — только у последнего стока,
остальным — свой тест (`find_test_for`: тест из files или `tests/test_<модуль>.py`), иначе внутренний
вид `smoke` (файлы изменились и компилируются). `executor`: `_smoke_check`, `file_state`; `smoke`
не делает предпроверку; зелёная предпроверка при уже `done`-соседях → `done` (`plan_stats.already_done`).
